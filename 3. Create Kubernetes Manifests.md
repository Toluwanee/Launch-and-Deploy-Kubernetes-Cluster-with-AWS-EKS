## Manifest files

Kubernetes manifests are sets of instructions that tells Kubernetes how to run your app. Kubernetes uses it to know what your app needs, like which containers to run, how many copies to create, and how much memory to allocate.... Manifests are helpful because, in general (even outside of Kubernetes), a manifest is an instruction/manual that tells a system how to set up and manage something.

Without manifests, Kubernetes wouldn’t know how to set up and manage your app automatically. This means you'd have to manually configure each container every time you deploy, which would be confusing, error-prone, and hard to repeat. Manifests make deployment simple, clear, and consistent.

A Kubernetes deployment manages the lifecycle, the scaling, the desired state, the healing of pods to keep the application healthy.

The container image URL in my Deployment manifest tells Kubernetes where my container image is stored so that it can pull the image and run it as a live container in the cluster.

## Service Manifest

A Kubernetes Service exposes my application(pods) to the outside world and route traffic to it. It is like a traffic controller that keeps traffic flowing to the right container on my app... You need a Service manifest to tell kubernetes to create or update the service (traffic controller). In it, you tell the service, which pods to target, the kind of traffic to accept, and the port to listen on.

My Service manifest sets up..kubernetes to expose my app to the outside world or other parts of my system
